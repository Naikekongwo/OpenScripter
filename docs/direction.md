# OpenScripter 方向与需求

本文是本轮确定下来的开发基线。脚本语言的具体语法、指令集与表达式尚未定稿，要等反编译原型机的 ScriptEngine 之后再补；本文只锁定不依赖语法细节的部分。由此拆出的待办条目见 `docs/todo/local.md` 的 R-xxx。

## 1. 定位与边界

OpenScripter 是 OpenCore 引擎配套的 AVG 剧本设计与演出预览工具，服务于一款经典 GALGAME 的重制。

- 使用者是作者本人。不面向团队协作，不做账号、权限、插件体系。
- 目标是把「写剧本 → 看演出 → 改一步」的循环压缩在一个窗口里。
- 下限是新脚本格式必须能无损表达旧游戏的指令集语义。
- 不等价于兼容：不读取、不保存旧游戏的原始脚本文件，只提供一次性转换路径。
- 上限是新格式可以带现代特性（变量、条件等），但具体特性不在此轮确定。

## 2. 形态

启动页 → 编辑页 → 全屏预览。

启动页负责创建工程、选择工程、最近工程。

编辑页是一个窗口，分区如下：

- 顶部：菜单与工具栏。
- 左栏：工程/章节树。点击章节，中栏切换到该台本。
- 中栏：台本节点列表，只读，表格式。
- 右栏上：当前步预览。
- 右栏下：当前节点的参数表单，这里是唯一的编辑入口。
- 底部：状态栏，显示当前工程、台本、步号与校验状态。

全屏预览把同一段演出放大到全屏，可随时退回编辑页。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 工程 | 一个目录加一份工程清单（manifest）。清单声明章节/台本、资源注册清单与工程设置。 |
| 章节/台本 | 一份文本脚本文件。章节树按清单顺序展示。 |
| 节点 | 台本中的一步，在界面上对应脚本文件里的一段连续文本。 |
| 指令 | 节点表达的演出动作。指令集待定。 |
| 预览 | 从当前节点起播的演出画面。不包含存读档、历史、自动播放等游戏系统。 |

## 4. 已确定的决策

- D1 真源：文本脚本。引擎的 ScriptLoader 解析它，编辑器解析同一份文件生成只读节点视图。
- D2 编辑入口：只有单步参数表单可以修改；台本视图与脚本文本在界面上都不可直接编辑。
- D3 节点映射：语言必须保证「节点 ↔ 连续文本区间」可逆。改节点只重写对应区间，其余文本原样保留，包括注释与空行。
- D4 语言待定：语法、指令集、表达式与控制流的具体形态等反编译结果。在此之前不得把语法写死，指令的描述必须可替换。
- D5 工程：目录加 manifest。启动页扫描目录；最近工程另行持久化，不写进工程文件。
- D6 资源：工程内放资源注册清单，按引擎的注册方式登记资源；预览与游戏同源，不自建一套资源系统。
- D7 UI：走引擎的 UI 体系（`OpenUI`），缺的能力优先提 OpenCore，确需过渡时放 `src/Compat/`；不引入第三方 UI 库。
- D8 预览范围：当前步或当前段落起播，可暂停、继续、单步、停止，可全屏；不含存读档、历史、自动播放。
- D9 布局：相对尺寸，不写死像素；窗口可缩放。
- D10 编码：脚本与清单统一 UTF-8。

## 5. 由决策推导的设计原则

- P1 指令以元数据描述，包括名称、参数、默认值与说明；台本列表、单步表单与校验都读元数据，执行语义另由代码实现。反编译后先填表，再补执行。
- P2 解析器与序列化器成对实现。节点到文本区间的映射是否可逆，是语言落地时的验收条件。
- P3 脚本格式带版本号，未知指令在载入与保存时的行为要明确定义，不能静默丢弃。
- P4 语言规范单独成文，与实现同步更新，避免解析器成为唯一事实来源。

## 6. 需求

### 6.1 启动页

- 新建工程：选目录、填名称、生成 manifest 与最小目录结构。
- 选择工程：打开已有目录并校验 manifest。
- 最近工程：列表展示，可移除失效项。
- 工程无效或缺失时给出可读提示，不留空白页。

### 6.2 编辑页

- 左栏章节树可折叠，点击章节切换中栏台本。
- 中栏节点列表的列包含步号、指令、角色、参数摘要、台词首段；选中行即当前步，滚动保持选中可见。
- 右栏预览保持 16:9，参数表单随选中节点刷新。
- 底部状态栏显示当前工程、台本、步号与校验状态。

### 6.3 单步编辑

- 表单字段由指令元数据生成，不在代码里为每条指令写死一套界面。
- 修改即时写回文本脚本，台本列表同步更新。
- 指令集未定期间，用占位指令表跑通「选中 → 改 → 回写 → 刷新」的链路。

### 6.4 预览

- 从当前步起播，支持暂停、继续、单步、停止。
- 全屏切换，全屏下保留必要的控制。
- 演出所需资源从工程的资源注册清单取；缺失时定位到具体节点并提示。

### 6.5 校验

- 语法错误、未知指令、标签与资源缺失。
- 校验结果定位到节点与文本区间。

## 7. 里程碑

### M0 UI 骨架

- 启动页与编辑页的分区全部画出来，使用假工程、假台本。
- 全屏预览以占位画面切换。
- 验收：启动 → 打开假工程 → 编辑页 → 全屏 → 返回，导航闭环。

### M1 工程体系

- manifest 格式、创建/选择/最近工程、目录扫描、空台本加载。

### M2 Compat 基础设施

- 单行与多行文本输入（含 IME）、滚动视口、面板布局。
- 对应 OC-003、OC-004、OC-005。

### M3 台本视图与单步编辑

- 节点列表、选中、表单生成、文本回写；先用占位指令表。

### M4 语言与解析

- 反编译结果落地：语法、指令集、解析与序列化、节点映射、校验。

### M5 预览

- 步骤起播、单步、全屏、资源加载。

### M6 旧脚本迁移

- 旧指令集到新脚本的无损转换，一次性完成。

依赖关系：M4 依赖反编译结果。M5 依赖 M4；若先用占位指令表提前做，会有返工。M2 可与 M1 并行。

## 8. 非目标

- 不做旧游戏脚本的读写兼容。
- 不做完整游戏试玩，包括存读档、历史、自动播放与成就。
- 不做资源编辑器；美术与音频仍由外部工具产出。
- 不做团队协作、账号与云同步。
- 不引入第三方依赖。
- 首版只保证 Windows 构建，跨平台不在本轮范围。

## 9. 未决项

- 脚本语法、指令集、表达式与控制流的具体形态，等反编译原型 ScriptEngine。旧系统的格式分析见 `docs/legacy-script-system.md`，命令表见 `LEGACY/analysis/commands.csv`。
- 旧脚本迁移的载体：编辑器内的导入命令，还是独立工具；一次性迁移后是否保留导入能力。
- 引擎侧接口：ScriptLoader 与 ScriptEngine 的职责划分及数据结构，对应 OC-007。
- 引擎子模块升级到 PackageManager，对应 L-006，影响资源清单与预览加载。
- 单步表单写长台词的效率。是否需要批量编辑或粘贴模式，等实际使用后再定。
- 资源注册清单里的路径基准：工程根，还是游戏资源根。

## 10. 与现有待办的关系

- L-005（预加载后空窗口）由 M0 取代。
- L-003、L-004、L-008 受资源注册方案影响，方案落地后重做。
- OC-007 从「共同定义数据结构」收窄为「共同定义语法与指令集」。
- OC-003、OC-004、OC-005 是 M2 的前置。
